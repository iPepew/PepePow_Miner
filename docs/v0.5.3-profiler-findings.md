# v0.5.2 RTX 3080 profiler findings

Profiler Pack captured a 600-second live pool run on HiveOS 0.6-230, kernel 6.12.0-hiveos #95, NVIDIA 610.43.03 and an RTX 3080 10 GB.

## Live result

- warm hashrate mean: 1.47904 MH/s
- warm median: 1.479 MH/s
- warm range: 1.471-1.487 MH/s
- warm standard deviation: 0.00311 MH/s
- accepted shares: 59
- rejected shares: 0
- GPU utilization: 100%
- memory utilization: 1%
- SM clock: fixed 1950 MHz
- memory clock: fixed 9251 MHz
- average board power: 197.86 W
- GPU temperature: 64-65 C

The GPU is compute-bound. PCIe, memory bandwidth, clocks, temperature and driver stability are not limiting performance.

## Autotune evidence

The selected v0.5.2 profile was `exact-mono64-u1` at 1,515,301 H/s, 25% above the validated v0.5.1 baseline. Unroll 2 was about 4.3% slower and unroll 4 about 27% slower. The split pipeline was about 1.8% below the selected monolithic profile.

## Static CUDA evidence

The production monolithic kernel uses 87 registers and a 176-byte stack. Static SASS contains a high density of FP64 arithmetic, control-flow reconvergence and device-library calls. This is consistent with the HooHash transcendental path rather than a memory bottleneck.

## v0.5.3 direction

The next profile should keep the monolithic 64-thread, unroll-1 baseline and test only consensus-validated transformations:

1. direct bit extraction for `fraction(sum / 1024)` without an FP64 divide/multiply;
2. derive the second nonlinear fraction from the first (`two = frac(2 * one)`), removing one fraction extraction;
3. skip zero nibbles only after the first cell of a row, preserving the row-boundary `sw = 0` transition;
4. optional constant nibble conversion table;
5. occupancy experiments with lower register caps and wider launch widths.

No profile is eligible for packaging unless every CPU/CUDA validation vector passes.
