# PepeW Miner 1.0 — устройство публичного пакета

Статус: основа и контракт упаковки; миграция текущего пакета ещё не завершена.
Целевая платформа первой версии: Linux x86_64 / HiveOS, NVIDIA CUDA, PEPEPOW.
Название продукта: **PepeW Miner**. Версия берётся из одного VERSION.
Внутреннее имя каталога и HiveOS: **pepew-miner**, без номера версии.
Имя архива: **pepew-miner-1.0.0-linux-x86_64-hiveos.tar.gz**.
Существующие теги не передвигать. Название первого публичного выпуска не означает
«первый в мире майнер PEPEPOW».

## Изученный образец

hoo_gpu-1.4.23.tar.gz, SHA256
1be57fe82cd6bcc1e5c48e93f3f86c9b08f7ff3964951d361b477761dbdcec6f.

В архиве один каталог hoo_gpu, исполняемый файл, 19 отдельных cubin,
libs/libcudart.so.12 и libnuma.so.1, адаптеры HiveOS/MMPOS и примеры запуска.
Бинарник и cubin не запускались. Отдельные cubin означают структуру поставки,
а не подтверждённую скорость или работоспособность на всех перечисленных GPU.

Полезные принципы: единый каталог, явные архитектурные файлы, локальные зависимости,
небольшие адаптеры платформы. Копировать чужие бинарники/ядра в наш продукт не нужно.
В присланном архиве не обнаружен отдельный LICENSE; право переупаковки его
компонентов этим анализом не устанавливается.

Не переносить поведение образца:
- h-config.sh пишет пароль и полную конфигурацию в setup.txt;
- h-run.sh пишет строку запуска в run.txt и использует некавыченный набор аргументов;
- PID через $! записывается после синхронного выполнения, а не после background launch;
- примеры содержат конкретный кошелёк;
- mmp-launcher.sh только формирует CMD, без выполнения в этом файле.
Наличие MMPOS-скриптов само по себе не подтверждает полноценную интеграцию.

встроенный fatbin. Внешние cubin нужны только при реализации и тестировании
соответствующего загрузчика.

## Контракт профилей

RTX и V100 входят в один продукт, но не обязаны использовать один бинарник
или одинаковую геометрию ядра. Выбор должен опираться на UUID/PCI bus identity
и вычислительную архитектуру; номера CUDA и nvidia-smi нельзя молча считать одинаковыми.
На смешанном риге — один процесс на выбранную GPU, явный профиль в журнале.

Для V100 сохранить оптимизированный путь и параметры из
[public-1.0-v100-integration.json](public-1.0-v100-integration.json).
Его threads=128 нельзя заменить нынешними общими runtime defaults=512.
Несовместимый профиль должен давать понятную ошибку до запуска worker.
Исторические результаты действуют для exact asset SHA256, не для новой сборки.
Экспериментальные e5a038e/9895bf3 не включать в stable по умолчанию.

## Конфигурация и жизненный цикл

- Сохранить контракт CUSTOM_URL / CUSTOM_TEMPLATE / CUSTOM_PASS / CUSTOM_USER_CONFIG.
- Экспертные аргументы разбирать как данные с shell-like quoting, без eval.
  Управляемые wrapper параметры отклонять, в том числе форму --option=value.
- Секреты хранить только в runtime-конфигурации с mode 0600; запись атомарная.
  Не включать wallet.conf, setup/run logs, PID, рабочие каталоги или кошельки в архив.
- Логи: /var/log/miner/custom/pepew-miner; runtime state: отдельный writable каталог.
  Перенос путей делать совместно с h-stats.sh и монитором, не одним переименованием.
- INT/TERM останавливает worker/proxy/monitor и дожидается их завершения.
  Ошибка одного worker должна отражаться exit code и конкретной причиной.
- Не рекламировать watchdog как защиту от зависания GPU, пока реализовано
  только наблюдение за существованием процессов. Не менять clocks/драйвер автоматически.

## Статистика и оформление

Стартовый экран: имя, версия, алгоритм, GPU / UUID / PCI bus, выбранный профиль,
драйвер, источник конфигурации. Пароль, полный wallet и сырой argv не печатать.
Каждая строка ошибки: компонент, понятная причина, следующий способ диагностики.

В h-stats.sh нужны числовые hs/temp/fan/power с одинаковым порядком устройств,
явные единицы, accepted/rejected/stale и uptime. Неизвестные данные не изображать
измеренным нулём. Недоступная статистика должна иметь определённое поведение.
Не заявлять совместимость MMPOS, TLS, failover, CPU mining или Windows без реализации.

## Упаковка и приёмка

BUILD_MANIFEST.json фиксирует package/version, source SHA каждого профиля,
CUDA/compiler/build flags, архитектуры, бинарные SHA256, имена выполненных тестов
и отдельные cpu_tested/gpu_tested/pool_tested. Поле «compiled» не равно «supported».

Сборщик должен использовать список включаемых файлов, один корневой каталог,
запрет абсолютных/traversal путей и внешних symlink, стабильные права 0755/0644,
SHA256SUMS для содержимого и отдельный SHA256 архива. Секретные/runtime файлы запрещены.
Не включать libcuda из драйвера. Нужные runtime-библиотеки определять по ELF
зависимостям и условиям распространения, не копировать libs чужого майнера.

Перед публичным 1.0: проверки quoting/config и stop/cleanup, статистика mixed GPU,
валидность пакетных хешей, корректность exact binaries на GPU, проверка принятых
shares по разрешённой процедуре. Сборка сама по себе не разрешает pool gate.
До этого пакет помечается preparation/RC; старый рабочий выпуск сохраняется.

и его redistribution notices. Пакет остаётся preparation, не stable 1.0.

в отдельный state root из целевой схемы ещё не выполнена. GPU watchdog и
recovery рабочего майнера обеспечиваются внешним разрешённым испытательным
контуром, а не process supervision этой оболочки.
