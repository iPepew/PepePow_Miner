Source inspection found an important confound: the baseline `matrix_row_hotrun8_word_stream` preloads two adjacent warm contributions before committing them in exact FP64/SW order. The reconverged state machine instead loaded and committed one warm cell at a time. Therefore, this comparison cannot attribute the entire loss to warp rendezvous alone. Lower static SASS instruction count/register count also did not predict speed:1968instructions/54registers for baseline versus1854/50 for the experiment, both80-byte stack and0compiler spills.

A default-off refinement restores the two-value warm preload inside reconvergence. It computes a second pure contribution only within the current packed word and commits it only if the exact first-cell SW update stays warm. Cold cells, zero-nibble updates, row packing, both rendezvous points and completion vote retain their order.
